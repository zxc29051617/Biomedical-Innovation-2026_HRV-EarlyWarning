# ACS ECG 標籤與重複紀錄的語義審查

2026-11-02。本文核對公開資料原文、作者程式與本專案既有彙總，供[OMI 研究草案](omi_study_protocol.md)後續凍結使用。**公開來源尚不能解釋115位患者不同紀錄的 OMI 0／1差異；不能將它當成已證實的多次就醫，也不能直接視為錯標。** 本輪未改標籤、選主要 ECG、建模或讀取 MIMIC。

## 已證實的資料語義

[資料原文 Methods](https://www.nature.com/articles/s41597-026-07278-0)說明：ECG 與造影以患者身分配對，保留造影前七天內所有可用 ECG，`Time_Interval` 是各紀錄距造影的分鐘數。OMI 來自造影報告的急性 culprit TIMI 0–1；AMI、STEMI、NSTEMI、UA 來自出院診斷。Table 2 提供患者 ID、ECG 檔名與相對時間，沒有 encounter 或 procedure ID。[PMC 全文對應段落](https://pmc.ncbi.nlm.nih.gov/articles/PMC13347058/)

這表示公開 CSV 的儲存單位是帶有來源標籤的 ECG 紀錄列；`Patient_id` 是分組鍵，不能自行當作一次急性事件的鍵。Table 2 用患者疾病描述各旗標，也不足以證明同患者所有列必須有相同旗標。哪份造影報告與哪次出院診斷對應至哪一列，仍缺少可重建的事件映射。

[本專案實際彙總](results/cath_metadata_patient_summary.json)確認公開 train 有17,960列／17,018個 ID，其中855位有多張 ECG；1,151列 OMI 陽性涉及1,139位患者，115位患者在不同列同時有 OMI=0與1。原始 train／test 的患者 ID 交集為0。這些結果是檔案計數，不代表已獨立確認患者身分、事件數或臨床真值。

## 公開來源尚未解答的問題

| 問題 | 目前能下的結論 |
|---|---|
| 同患者不同 OMI 標籤是否來自不同就醫或多次造影？ | 可能，但原文未給逐例解釋或公開事件映射，不能確認 |
| 同一次造影之前的 ECG 是否一律繼承相同造影標籤？ | 原文未提供可執行的逐列分派演算法或多對多配對處理規則 |
| 同患者多張 ECG 能否依 `Time_Interval` 排成病程？ | 只有先證明共用同一造影時點才成立；目前不能直接排序成病程 |
| 可以挑最大或最小 `Time_Interval` 當到院第一張嗎？ | 不可以；相對造影的時間不提供到院時間或同次就醫邊界 |
| `Paced`／`VF_VT` 是否描述輸入這張 ECG？ | 不可預設；原文旗標擷取涉及出院診斷／手術紀錄，不代替當張節律判讀 |
| 檔名或 WFDB 標頭若有日期，能否補出首次到院？ | 仍需確認該日期的定義、去識別化方式及造影／就醫對應；日期存在本身不夠 |

未知原因至少可能包含不同事件、不同配對範圍或資料／標籤整理問題。這些都是待查假說，不能從115這個總數辨別哪一個成立，也不能憑 ECG 長得相似來裁定臨床 OMI 真值。

原文 Technical Validation 的標籤核對亦使用 ECG 波形與臨床診斷，並報告經反覆核對後與專家一致。[原文 Label consistency validation](https://pmc.ncbi.nlm.nih.gov/articles/PMC13347058/) 因此，**標籤完全獨立於被評估 ECG 的程度尚不明確**。這是參照標準可能含待測 ECG 資訊的偏差（incorporation bias）疑慮，不是認定作者錯標；其影響需要原始裁定流程才能判斷。專家一致也不等於本團隊已驗證每列標籤。

## 作者公開程式能解決的範圍

本日核對的[作者 repository](https://github.com/catcatgirl/validation-code)根目錄只有 `.gitattributes`、README DOI badge 與 `validation_code.py`；沒有可見的 ECG／造影事件配對、逐列標籤裁定、完整訓練或患者切分實作。核對的程式 blob 為 `4c595a843a4360a6e55abd56fe326cbaf1f24ef8`。

[validation_code.py](https://github.com/catcatgirl/validation-code/blob/main/validation_code.py)主要計算 WFDB 長度／取樣率、振幅及低頻基線統計；它不會解釋115位患者的標籤變化。部分函式把 NaN 改成0、短訊號補0，這種處理不應直接搬成本研究的品質通過規則。缺失、短長度及無法量測須保留狀態；訊號統計通過也不能替代 ST 幅度與節律判讀。本輪只審查程式，沒有複製其實作。

## 無法取得事件映射時的工程基準建議

以下為本專案的方法建議，尚未取代研究草案或執行建模。

1. **分析單位固定為 ECG 紀錄列。** 使用來源列提供的 OMI 標籤；稱為「造影前 ECG 的來源急性阻塞標籤辨識」。納入完整預先指定時間範圍與所有結局，不能對陽性選最接近造影、對陰性另選最早一張。
2. **患者為隔離及不確定性單位。** 同患者所有列留在同組，患者 bootstrap 保留其全部列。公開報告同時列 ECG 數與不同患者數；敏感度分母是陽性 ECG 時，要明確如此標示。
3. **保留115位患者的原始列，不自動修成 any-positive。** 增設患者內標籤變化旗標，作資料可追溯與預先指定的敏感度分析；旗標不得進模型。若無證據證明錯誤，不為提高分數刪除全部差異患者。
4. **先處理檔案身分，再談獨立樣本。** 核對 CSV 檔名唯一性、raw／median 一對一關係、重複 waveform hash，以及同一 waveform 是否被不同列或不同患者映射。重複列或跨組重複波形必須在模型前依固定規則處理；不能把標籤矛盾的同波形任選一標籤當真值。
5. **固定一張 ECG 的分析僅作敏感度檢查。** 若需要減少多張患者的權重，可於看模型成績前，按公開 seed 與 ECG 記錄鍵的穩定雜湊排序，每位患者取一張；排定時不使用 OMI、STEMI、造影時間或模型分數。這張只是可重現的選樣，不能稱到院第一張或同次事件代表。品質不合格照實報拒答，不依結局換張。
6. **關鍵子群來自同張 ECG 的盲判。** 同列 OMI=1且來源 STEMI=0 的418位患者是診斷交集，不能直接作一般 ST 幅度陰性子群。波形檢視只揭露套門檻必要的當張資訊，來源標籤與時間間隔由資料管理端保留。
7. **限定結論。** 此基準可驗證重現性、資料覆蓋與 ECG 層級分類；不證明首次到院分流、患者事件檢出率、實際心導管優先序或急診族群的 PPV。即使工程基準成績良好，也仍需獨立臨床事件資料驗證。

若後續取得資料，最低需補：去識別化的就醫／造影事件鍵、每份 ECG 與事件的映射、可核對的到院／ECG／造影時間，以及各列標籤來源與修訂規則。這些資料應在任何宣稱「第一張 ECG」或「單次急性事件」的主分析之前完成核對。此次未聯絡作者或建立外部 issue。
