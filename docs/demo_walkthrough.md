# 三分鐘展示與本機操作

這個版本已完成「逐時重播、訊號品質、既有模型分數、研究證據」的操作流程。展示要讓人看懂系統如何處理資訊不足，以及目前研究證據支持到哪裡；不能把介面順利運作當成臨床有效。

公開簡報、錄影與分享請使用內建的三個合成情境。真實病例 JSON 雖已移除原始識別碼與日期，仍是患者層級資料，僅在具資料使用權限的本機環境檢視。

## 開啟原型

在專案根目錄執行：

```sh
python scripts/serve_demo.py
```

使用瀏覽器開啟 `http://127.0.0.1:8765/`。這個服務只提供 `web/` 中列入白名單的介面檔案，不提供原始資料或患者 JSON。預設載入合成情境，不會自動讀取真實資料。

若電腦限制本機服務啟動，可直接用瀏覽器開啟專案內的 `web/index.html`；頁面不需要安裝前端套件或連線下載函式庫。若只是連接埠被占用，可執行 `python scripts/serve_demo.py --port 8766`。

## 三分鐘展示腳本

開始前按「回到合成展示」，選擇「常規資訊＋歷史 RR」，先不要勾選回溯事件。下列時間是講解節奏，不是資料的實際經過時間。

| 時間 | 操作 | 可以直接使用的講法 |
|---|---|---|
| 0:00–0:25 | 指出「合成展示」及「回溯研究原型」標示。 | 「我們研究的是未來六小時首次開始持續升壓劑輸注的事件。這裡用合成情境展示操作；分數不是病人的已校準風險，也不提供診斷或給藥建議。」 |
| 0:25–1:00 | 選「穩定觀察」，按左側回到起點按鈕，再逐步前進或播放。 | 「每次只顯示當前時間以前的觀察值。生命徵象、RR 特徵和模型分數一起更新；缺值會留白，不會拿下一個時點的資訊補上。」 |
| 1:00–1:40 | 選「訊號間斷」，回到起點，再按前進四次到合成情境 ICU +10 小時；切換「全風險集合常規基準」，再切回歷史 RR。 | 「這一刻 ECG 不能提供可接受的 RR，所以四組配對模型停止出分。常規基準仍可能有分數，但沒有 RR 分數不代表沒有風險。工程品質通過，也還不能證明這些是正常 NN 間期。」 |
| 1:40–2:15 | 選「循環變化」，觀察模型選單與通知門檻，再勾選「顯示已到達的回溯事件」，把時間移至末端。 | 「事件資訊只供回顧，未到事件時不揭露事件時間。事件開始後停止預警；追蹤終點不沿用最後分數。通知採每組模型的門檻和六小時不重複通知規則，仍需驗證實際工作負擔。」 |
| 2:15–3:00 | 切換「研究證據」，指出配對比較與覆蓋率。 | 「真正的研究證據在這裡：已完成 340,354 個 ECG 片段，其中 142,489 個通過目前工程篩選；配對驗證包含 630 位患者、41 個事件。目前歷史 RR 的差值區間跨零，沒有清楚增益證據，而且搏動定位仍有已知缺口。我們下一步要先驗證量測，再檢驗同等誤報負擔下是否有額外價值。」 |

圖上的百分比只是模型輸出格式。個別病例的曲線先升、後升，或有沒有跨過門檻，都不能替代患者隔離的整體驗證。若被問「所以已能提早救人嗎」，可以直接回答：「目前還沒有這項證據；我們已把可重跑的研究管線、完整開發結果與可操作原型做出來，下一關是訊號量測與保留測試驗證。」

## 在本機檢視真實開發病例

此步驟需要本機已有完整 M2 產物、可信的模型檔及科學計算環境。介面本身不解碼 ECG、不重新訓練模型，也不從網站下載患者資料。

目前工作機可在專案根目錄執行：

```sh
/home/zxc29051617/miniforge3/envs/lab410/bin/python scripts/export_replay.py
```

匯出預設只使用 `validation`。程式檢查訊號完成狀態、來源指紋、固定患者切分、模型與門檻的一致性，再使用既有五組模型產生分數；不開啟保留測試特徵、不重訓。選例使用預先指定的類別與固定雜湊排名，私有選例 manifest 在預測前保存，不根據分數挑選病例。

成功後會有三個本機檔案，全部位於 Git 忽略的 `artifacts/replay/`：

- `replay.json`：供介面匯入的匿名病例與相對 ICU 小時。
- `selection.private.json`：可重現選例所需的私有紀錄，包含內部識別碼，不能匯入介面或分享。
- `export_summary.json`：匯出狀態、數量與來源指紋。

目前這次固定選例共 3 例、224 個逐時點，其中 113 個時點有可接受的當下 RR。事件病例在事件前最後六小時沒有合格 RR，因此該段配對模型不出分；這是覆蓋限制的實際呈現，沒有為了展示漂亮結果而事後換例。

在頁面按「匯入本機病例 JSON」，選擇 `artifacts/replay/replay.json`。成功後應看到「本機研究資料」，病例來源也應改成 M2 validation。再用病例清單、播放與模型選單檢視。匯入失敗時仍保留上一份資料，不能把仍在畫面上的合成情境誤認為新檔案。

留意以下幾個行為：

- 當下 RR 被拒絕時，RR 數值與四組配對分數均為空值；常規全風險集合基準可獨立出分。
- 六小時覆蓋數來自已凍結的六個逐小時片段。`?` 表示該片段沒有單獨匯出，不能直接當成品質拒絕；總數可能因此多於畫面上的勾號。
- 時間可以走到風險追蹤終點。介面補的是全部空值的終止停點，不會製造新的生理觀察或模型預測。
- 開啟回溯事件後，也只會顯示已到達的事件時刻。事件標記不進入模型輸入。

瀏覽器的匯入檢查負責欄位、數值、時間與品質的一致性，不能取代 Python 匯出程式的來源指紋與模型檢查。真實展示請使用正式匯出的檔案，不要手動改分數、門檻或來源標示。

「匯出目前觀察」會下載當前時點摘要。真實研究模式下，這個下載檔也含患者層級觀察，應留在受控本機，不放進 `web/`、Git、簡報附件或公開分享資料夾。結束時按「回到合成展示」或關閉頁面；頁面不把匯入病例存到瀏覽器持久儲存空間。

## 遇到錯誤時

若匯出提示來源、模型或選例指紋不一致，先核對原有產物是否改動，不要刪除私有 manifest 來強制通過。`test` 不是可匯出選項；這個展示流程不承擔保留測試評估。

若頁面無法匯入，先確認選的是 `replay.json`，而不是選例 manifest、摘要或模型檔。檔案必須符合 `hrv-replay-v1`，大小不超過 8 MiB；缺值用 `null`，不可用字串、NaN 或無限大代替。仍無法載入時，保留錯誤訊息，由團隊核對來源，不手工填補患者數值。
