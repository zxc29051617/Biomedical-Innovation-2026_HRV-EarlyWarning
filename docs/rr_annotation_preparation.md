# ICU 雙人盲標：固定選例準備

承接[同參考搏動對照規格](timing_comparison.md)的 20 例試行，這個工具只凍結後續需解碼與判讀的片段，不讀取原始 ECG、不產生偵測器點位、不宣稱已完成波形包或醫學判讀。它可在僅有 Python 標準函式庫的環境執行。

## 事前選例規則

1. 固定 seed `20261101`，只使用原患者分組中的 **train**。排除 `reports/local/spotcheck/selection.private.json` 既有六例所屬的六名患者；不以新 ICU 或另一次住院把同一人重新納入。
2. 使用已完成 M2 的逐時模型表與 epoch 表，僅以相同 ICU、完全相同 `landmark=endtime` 連接。讀取患者／住院／ICU 身分、當下時間與 v1 接受決策；不讀模型特徵、事件標籤、事件時間、分數或 epoch 內的 RR 數值。只有密集 event audit、沒有對應逐時模型列的片段不會進入選例。
3. 先在 accepted 組依患者雜湊排名選 10 名；再從尚未選過的患者中，依 rejected 組患者雜湊排名選 10 名。每位患者在所屬組中再以 ICU／片段時間雜湊選一個五分鐘窗，避免住院較長者因片段多而重複占名額。
4. 任一組不足，直接停止並報不足；不從 validation／test 補人、不換 seed。這個固定組別先後及 10／10 配額是標註流程試行設計，**不是全體患者或品質狀態的比例估計**。
5. 不額外依解碼狀態、波形外觀、臨床結果或新方法改善程度篩掉 rejected 片段。未來若凍結片段無法解碼或判讀，保留失敗／未知紀錄，不默默換成較容易的例子。
6. 選出 20 名不同患者後，另外以不含品質組的雜湊混排，再依序命名 `RR-A001` 至 `RR-A020`。這些代號不是患者 ID，也不按 accepted／rejected 分組排列；映射只留私有 manifest。

## 執行與輸出

```sh
python scripts/prepare_rr_annotation.py
PYTHONPATH=src python -m unittest discover -s tests -p test_rr_annotation.py -v
```

工具先驗證完整 M2 來源、固定分組、原六例 manifest 與訊號程式指紋；資料庫唯讀，來源大小與修改時間在選例前後須一致。已存在的選例或模板均拒絕覆寫，不能透過重跑偷偷換人。預設只寫 Git 忽略的 `artifacts/rr_annotation/`，檔案權限為 0600：

- `selection.private.json`：保存 20 個匿名代號對應的患者／住院／ICU ID、原始起訖時間、品質組、候選池雜湊及來源指紋。此檔不能交給第一階段盲標審閱者，也不能放入 Git、網站或公開簡報。
- `reviewer_template.json`：只含匿名片段代號、預計五分鐘長度、目標導程及兩位審閱者的空欄位。沒有患者 ID、原始日時、accepted／rejected 決策、臨床事件或模型分數。實際導程、取樣率、樣點數與波形雜湊仍為 `null`，明確標記 `waveform_package_ready=false`。

模板保留訊號區間、搏動、節律區間、NN 適用區間與共識理由欄位；不會自動填任何心律或正常 NN 結論。兩組空欄位只是資料格式樣板，正式標註時應給每位審閱者**各自的私有副本**，不能讓第二位看到第一位的作答。各自原始標註必須保存，共識修訂另存。

若選例 manifest 已寫入、但模板寫入時遇到中斷，仍保留第一份 manifest，不重新抽樣；先核對已凍結選例，再從它恢復模板。工具沒有自動刪除或覆寫已存在產物的選項。

## 下一步才會完成的部分

恢復科學 Python 環境後，需依凍結 manifest 讀取同次 ICU 的原始五分鐘 II 導程，保存原取樣率、資料缺口與原始波形雜湊，並驗證來源與時間對齊。未解碼前不能假定每段都有完整 II 訊號，也不能預先填 125 Hz。

提供審閱者的波形只顯示相對樣點／毫秒刻度，不顯示原日期、品質決策、給藥終點或偵測器點位。審閱者需具 ECG 判讀能力並各自有資料使用權限。正式 20 例之外先完成定位點操作規則與教學練習，再進行獨立判讀、分歧審查及凍結演算法對照。20 例本身不足以代表全體 ICU 準確率或證明臨床預警效益。
