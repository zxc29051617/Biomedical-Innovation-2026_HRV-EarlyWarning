# RR 額外資訊的探索性對照

這是看過 v1 結果後提出、在新模型擬合前寫定的追蹤分析，不能稱為未看資料的預先登錄或獨立確認。終點、v1 訊號特徵、患者分組及保留測試政策均不變。規格另存 [rr_incremental_controls.json](../configs/rr_incremental_controls.json)，執行器會核對內容，避免事後只挑有效的對照。

## 這次要分清楚什麼

原本「常規資訊＋RR」的差異可能來自平均心率、資料是否有被記錄、歷史資訊量或變異量本身。這次固定五組相互包含的特徵，全部使用相同的當下 RR 工程通過時窗：

| 模型 | 內容 | 要回答的問題 |
|---|---|---|
| `routine` | 原本常規生命徵象與年齡 | 重現既有配對基準 |
| `availability` | 上組＋六段有效遮罩、有效段數、斜率是否可計算 | 只是知道資料有沒有留下，是否已能改變分數？ |
| `ecg_rate_history` | 上組＋六段 mean RR、60000／mean RR 及兩者斜率 | 同一 ECG 的平均速率與歷史已提供多少資訊？ |
| `rr_variability_history` | 上組＋六段 SDRR、RMSSD of RR | 在速率／歷史／可用性之外，變異特徵是否仍有增量？ |
| `rr_variability_trend` | 上組＋SDRR／RMSSD 斜率 | 同樣歷史資料的趨勢表示是否改變預測表現？ |

主要對照為 `rr_variability_history − ecg_rate_history`；其餘三個相鄰對照都完整報告，不挑最佳模型。60000／mean RR 是平均 RR 的倒數速率，不是逐搏瞬時心率的平均。mean RR 與倒數是同一資訊的兩種表示，用來控制線性模型對速率關係的表達能力，不宣稱兩份獨立訊號。

斜率需要至少三個有效片段，只從已凍結的六個採樣點計算，不插補、不用密集陽性事件 audit epochs。完整六點時，斜率是歷史數值的線性組合；缺值時其表示依可用片段而變，不能將斜率增益稱為額外生理資訊。

## 擬合與驗證限制

補值與標準化只在非截尾訓練患者時窗擬合。模型沿用固定 C=1、無 class weighting 的 logistic regression。`routine` 先精確核對原 v1 的 AUROC、AUPRC、Brier 與通知門檻，通過才繼續其餘模型。

常規欄位沿用原本的缺值指示。所有 RR／衍生欄位只做訓練中位數補值，**不再自動生成重複的缺值指示**；五組中的後四組共用明確的有效遮罩。若每增加一個 RR 欄位就重複加入相同遮罩，L2 正則化會改變對可用性訊號的有效懲罰，可能被誤認為變異量增益；本版在任何新擬合前已修正此問題。

四組對照共享 200 次驗證患者 bootstrap，固定預測、不重訓，以 candidate−baseline 的 AUPRC／AUROC 及 baseline−candidate 的 Brier 表示改善。單一類別的抽樣共同跳過並報次數；95% 區間未校正多重比較，也不包含訓練／模型選擇的不確定性。

通知仍採各模型訓練陰性分數第 99 百分位與六小時不重複規則，完整報告實際誤報、事件捕捉、提前時間及覆蓋。**這不是同等實際誤報負擔比較**，不能據此宣稱能在同樣工作量下更早預警。將來若選操作門檻，需在開發資料內另鎖定校準方案，不能用保留測試挑門檻。

此對照也沒有完整常規生命徵象歷史／斜率模型，不能主張勝過所有常規趨勢預警方法。固定開發驗證只有 41 個可評分事件，且 v1 尚未確認 NN 與量測準確度；即使有正差值，也只能解讀為特定模型家族與目前工程特徵的探索性增量。

## 資料隔離與執行

```sh
# 純標準函式庫可完成資料、來源及特徵一致性檢查。
python scripts/evaluate_rr_controls.py --output-dir artifacts/rr_controls/preflight

# 需本機科學依賴與原有受控資料；不可把患者資料搬到公共 CI。
python scripts/evaluate_rr_controls.py --fit --output-dir artifacts/rr_controls/run_01
```

輸出只允許忽略的 `artifacts/rr_controls/`，拒絕覆寫既有結果或來源；plan 在首次擬合前保存。每次讀取特徵前，在同一個 SQLite 唯讀交易內驗證來源、固定患者分組與 model-table 雜湊，資料有 test／未知 split 或跨分組患者會拒絕。結束前再核對來源未變動。產生的模型與執行紀錄仍留本機。

真實 preflight 已核對 76,970 個訓練與 18,025 個驗證配對時窗，其中非截尾為 70,633／16,275，與原 M2 相同；沒有讀取保留測試特徵。11 月 1 日因原科學環境不可見而停在 preflight；**11 月 2 日找到另一個本機科學 Python，五組模型已實際完成擬合及開發驗證**。以下實測結果與先前 CI 合成測試分開記錄。

程式已於[正式 CI](https://github.com/zxc29051617/Biomedical-Innovation-2026_HRV-EarlyWarning/actions/runs/41305759671)通過完整 409 項測試，包含合成資料的原基準重現、訓練內補值、RR 不重複增加缺值指示，以及重新開表後在特徵讀取前重驗來源。這提供實作驗收，不提供新患者模型的 AUPRC 或臨床增益結果。

原 MI 專案曾研究部分與 M2 固定分組重疊的患者，詳見 [MI 可行性審查](mi_feasibility_review.md)。本流程仍不開 M2 保留測試，但不宣稱這些患者從未出現在任何前作。

## 2026-11-02 真實資料結果

執行來源為 commit `65e52029a829491433210102c98aae370fd2833a` 中的既有規格與程式，未為本次結果修改特徵、模型、門檻或重現容許差。使用 Python 3.11.17、numpy 2.4.6、scipy 1.17.1、scikit-learn 1.9.1、joblib 1.6.0、threadpoolctl 3.7.0；環境與 v1 不同，但原常規基準的 AUROC、AUPRC、Brier 與通知門檻全數通過既有重現檢查（相對容許差 1e-8、絕對容許差 1e-10）。五組皆無收斂警告。沒有安裝或修改借用的環境，也未讀取保留測試特徵／分數。

五組比較均包含相同 630 位非截尾驗證患者、16,275 個時窗與 41 個可評分事件；包含截尾的通知觀察為 649 位患者、18,025 個時窗。完整彙總與來源指紋見 [機器可讀結果](results/rr_incremental_controls_summary.json)。模型權重只留本機。

**決策：不把 RR 變異模組升格為已驗證的預警增強。** 現有結果支持繼續區分平均速率、監測可用性與 RR 變異，不支持用更高的模型複雜度掩蓋量測與覆蓋限制。任何下一版主張，仍須獨立量測驗證、強常規歷史基準、訓練內警報校準及完整母群評估。以上都是開發追蹤結果，不是臨床或保留測試結論。
