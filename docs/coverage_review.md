# RR 患者與監測時間覆蓋：實際 development 稽核

本次只讀取已完成、凍結的 M2 訓練／開發驗證資料，沒有修改品質規則、重訓、讀取保留測試特徵或分數。最重要的結果是：**覆蓋不足主要不只發生在 RR 偵測階段。** 開發驗證的 247 個有預警機會事件，72 個至少有一個已規劃的當下片段，68 個至少有一個可解碼片段，41 個至少有一個工程篩選通過片段。

72／247 是在**既有資料庫範圍、以 II 為目標導程、每小時更新前最後五分鐘規劃**之下，把所有已規劃片段都假定能成功使用的理想上限。它不是所有導程、不同時間取樣策略或其他資料集的絕對上限；規劃本身只根據同次 ICU 的 waveform record 時間重疊，不保證有 II 導程、訊號完整或能通過品質篩選。

## 執行方式與分母

```sh
python scripts/review_coverage.py
PYTHONPATH=src python -m unittest discover -s tests -p test_coverage_review.py -v
```

工具只需 Python 標準函式庫。15 項必要測試已通過，涵蓋 test 列在解析特徵前拒絕、唯讀資料庫、精確當下時間點、歷史計數一致性、事件／患者／時窗分母、部分小時、互斥狀態、非互斥原因及輸出路徑防護。實際完整掃描 814,154 個 development 時窗，私有執行產物為 `reports/local/coverage_review/summary.json`；供版控的[純彙總 JSON](results/coverage_review_summary.json)不含患者 ID、時間戳、個別數值或本機路徑。

進入掃描前，核對既有模型表、完整訊號工作、隊列、固定患者分組及來源指紋，並拒絕含 test／未知 split 的模型表。資料庫以唯讀方式開啟，SQL 明確限定 `train,validation`，再以 `ICUSTAY_ID` 與完全相同的 `landmark=endtime` 連接當下片段；不使用依陽性事件額外抽取的密集五分鐘 audit epochs。來源大小與修改時間須在掃描前後一致；這不是重解碼或逐原始波形位元組驗證。

development 成人基礎隊列為 13,986 位患者、18,680 次 ICU，其中 3,862 次首次持續輸注事件包含初始六小時內已開始者。實際進入逐時風險集合後為 11,366 位患者、14,747 次 ICU、1,222 個有正標籤預測窗的事件，合計 806,752.17 個實際監測小時。以下事件覆蓋率以後者為分母，不把初始六小時已發生事件放入可預警分母。

## 缺口發生在哪裡

下表是 development 當下時窗的互斥分類，合計 814,154：

| 當下狀態 | 時窗 | 佔完整風險時窗 |
|---|---:|---:|
| 沒有已規劃當下片段 | 588,854 | 72.33% |
| 有規劃，但解碼不可用或被解碼器拒絕 | 14,006 | 1.72% |
| 可解碼為完整或部分訊號，但工程篩選拒絕 | 116,299 | 14.28% |
| RR 工程通過 | 94,995 | 11.67% |

「沒有已規劃當下片段」只表示這個整點最後五分鐘沒有完成規劃的快取列，**不表示該患者在整次 ICU 沒有任何 ECG**。例如波形可能出現在別的時間，或別的取樣策略才會用到。改善偵測器本身不會補出這些缺少的當下紀錄。

可解碼的 `partial` 狀態也不保證完整五分鐘；非有限值等來源缺口仍會進入工程拒絕。因此不能把 116,299 個片段全部稱為「演算法誤拒」。

development 的主要工程原因如下；同一片段可以同時觸發多項，**不可相加當成拒絕片段總數**：

| 原因代碼 | 時窗 |
|---|---:|
| `nonfinite_samples` | 38,726 |
| `suspected_clipping` | 38,543 |
| `too_many_screened_rr_intervals` | 36,042 |

| `low_block_beat_agreement` | 16,661 |

解碼原因包含 `no_decodable_lead_ii` 13,592、`lead_ii_absent` 12,605、`overlapping_signal_conflict` 598、`incompatible_sample_grids` 162；它們同樣非互斥，也可能只是某個來源的警示而其他來源解碼成功。完整原因與分組分母保留於 JSON。訊號缺失、真實異常心律、定位錯誤與規則誤拒必須分開核查，不能僅因拒絕多就放寬門檻。

## 被保留的資料是否相同

粗年齡層的當下工程通過監測時間比例為：18–44 歲 **15.00%**、45–64 歲 **14.07%**、65–89 歲 **9.17%**、年齡去識別化為超過 89 歲者 **6.27%**。這是未調整的描述統計；同一患者可有多次 ICU，甚至跨年齡層，不能把各層患者數直接相加。

完整 development 非截尾時窗的陽性比例為 **0.825%**，當下 RR 工程通過子集為 **0.692%**。這表示保留子集的組成與完整風險集合不同；不能由此單獨判定因果選擇偏差、年齡造成訊號較差，或將不同子集的模型分數直接比較為 HRV 增益。

## 對下一步的影響

先保留 v1 與患者分組，利用獨立標註檢查定位準確度，並依拒絕原因核對原始片段，區分可修復的定位／規則問題與真正沒有足夠資料的片段。任何替代導程、較早的歷史窗或不同取樣策略，都要先固定新的資料可得時間規格，再重新盤點；不能把本次上限沿用到新策略，也不能回填當時不存在的資訊。

即使量測改善，現有預警題目仍須同時面對低監測覆蓋與有限事件數。是否改做 MI 應比較另一題的患者數、標籤時序及獨立驗證能力，不能僅因另一份資料的 ECG 筆數較大就認定一定比較適合。這份稽核沒有選新疾病、改終點或查看保留測試效能。
